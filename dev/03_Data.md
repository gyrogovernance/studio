# Data and provenance

## Native records

Studio uses Open WebUI's database, file storage, Knowledge index, and native export functions. Chats retain conversations and tool activity. Notes hold working documents. Search and conversation references support continuity across tasks. Human corrections can be recorded in the conversation and incorporated into the working document.

| Record | Storage and use |
| --- | --- |
| Chat | Messages, model responses, tool calls and results, and conversation metadata |
| Note | Editable document and native Note metadata |
| Knowledge | Collection and file records, extracted content, indexed passages, and document metadata |
| Workspace configuration | Model presets, prompts, skills, native Tool definitions, valves, and installation state |
| Export | Native chat or Note export selected through the application |

These native records provide MVP persistence and traceability. A dedicated finding-decision database or custom session export is not part of the current data model.

## Gadget result format

The gadget runner returns a JSON string with schema version `studio.gadget.v1` as its native Tool result.

| Field | Content |
| --- | --- |
| `schema_version` | Gadget result format version |
| `run_id` | Unique execution identifier |
| `gadget` | Gadget identifier |
| `model` | Requested inference model identifier |
| `created_at` | Execution start time in UTC |
| `source` | Supplied text and its SHA-256 fingerprint |
| `instructions` | Additional scope or constraints passed to the tool |
| `prompt_source` | Source repository, path, source fingerprint, copyright, and license |
| `status` | `complete`, `incomplete`, or `failed` on return |
| `passes[]` | Step number, prompt fingerprint, reference fingerprint when applicable, model output, available usage, reported model, and finish reason |
| `human_verification` | `pending`; execution does not record a human approval |
| `error` | Present when a step fails or stops before completion |

The source is the text supplied to the tool. Page or section labels are preserved when included in that text. The runner does not independently resolve or verify source locators generated by a model.

Source inputs above 200,000 characters are rejected rather than truncated. Provider context and output limits can be smaller. Meta-Evaluation includes earlier prompts, references, and outputs in later calls. A failed step or an output-limit stop ends the sequence; completed pass outputs remain in the returned result.

Generated review content remains text within each pass. The runner does not validate individual findings against a separate findings schema. The application retains the result through its native chat behavior; temporary chats and deletion follow the instance's native settings.

## AI Inspector port provenance

The source is the AI Inspector Chrome extension, package version 1.2.0, at `gyrogovernance/apps`. The recorded checkout baseline is `6cc030a98bed32a23dbb0491c9a67e9137396165`. The gadget manifest records the fingerprint of the actual local prompt source used during extraction.

| Native Tool | Source in `src/lib/prompts.ts` | Execution |
| --- | --- | --- |
| Policy Auditing | `POLICY_AUDIT_TASK` | One call extracting claims, evidence, and relationships |
| Policy Reporting | `POLICY_REPORT_TASK` | One call producing an attributed executive synthesis |
| Meta-Evaluation | `generateMetaEvaluationPass1`, `generateMetaEvaluationPass2`, `generateMetaEvaluationPass3` | Three sequential calls for detection, consolidation, and suggested revisions |
| Text Sanitization | `SANITIZE_TASK` | One call proposing text cleanup and explaining changes |
| Quality Improvement | `IMMUNITY_BOOST_TASK` | One call applying the source editorial criteria |

`scripts/port-inspector-gadgets.py` extracts the source templates into `backend/open_webui/studio/data/gadgets-v1.json` and generates the native adapters under `data/gadgets/`. Its source checkout path is configured in the script. The MIT notice is bundled with the adapters.

The shared runner adds execution instructions for source handling, citation preservation, limitations, and avoiding recursive tool calls. Text Sanitization adds preservation of meaning and sentence structure unless rewriting is requested. Quality Improvement is framed as editorial work. These adaptations do not add diagnostic scoring.

The extension's diagnostic analyst prompts, metric calculations, report generator, fixed comparison protocol, and diagnostic imports are not ported. Their contribution metadata and transcript handling are not used in Studio.

## Framework sources

`backend/open_webui/studio/data/frameworks-v1.json` defines five Knowledge collections with eight documents.

| Collection | Bundled edition or material |
| --- | --- |
| EU AI Act | Regulation (EU) 2024/1689, original Official Journal text published 12 July 2024 |
| NIST AI Risk Management Framework | AI RMF 1.0, NIST AI 100-1, January 2023 |
| NIST Generative AI Profile | NIST AI 600-1, July 2024 |
| OECD AI Principles | OECD/LEGAL/0449, official English Recommendation, amended 2024 |
| The Human Mark | `THM.md`, `THM_Grammar.md`, `THM_Specs.md`, and `THM_Terms.md` |

Each document entry records its filename, publisher, source URL, edition, retrieval date, SHA-256, and reuse notice. The bundled files are source snapshots. Changes require a versioned source update and review of the applicable reuse terms.

Knowledge uses the instance's extraction and embedding configuration. Extracted passages retain the metadata supported by the native pipeline, including page metadata when produced by the extractor. Framework installation state is separate from the source manifest.

Meta-Evaluation directly includes Grammar, Human Mark, and Terms in its corresponding passes and records their fingerprints. The Glossary displays sections from the bundled Terms and Grammar with attribution. Knowledge retrieval remains available for other document work.

## Data destinations and access

| Destination | Material |
| --- | --- |
| Instance database | Profiles, chats, Notes, Knowledge records, configuration, and installation state |
| Instance file and vector storage | Uploaded documents, extracted/indexed material, and runtime assets |
| Selected inference provider | Task instructions, supplied text, references, and previous passes sent for generation |
| Selected embedding or extraction provider | Document content needed by the configured indexing pipeline |
| Export or share destination | Material included in an explicit native export or share operation |

Local inference and local embeddings use the configured local services. Hosted inference, external extraction, and external embedding services process the material sent to them. Instance administrators control provider connections and resource access.

Provider credentials belong in the instance's connection settings or local environment. Keep credentials, runtime databases, uploads, and local exports out of source control. Backups must cover the database and the associated files and vector storage required by the deployment.

Bundled framework documents are reference resources. Their reuse terms do not license private chat content or drafts for publication. Sharing work or contributing it to another project requires an explicit choice with the applicable terms.
